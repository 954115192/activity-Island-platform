# 内置局域网文件传输

## 范围与交互

桌面应用内置 LocalSend v2 兼容服务，随应用启动，不依赖插件启动。支持文件拖入灵动岛、附近设备选择、接收确认、多文件传输、进度、取消和错误恢复。

发送：文件拖入岛面 → 宿主展示拖放提示 → 松开加载文件 → 点击附近设备 → 等待接受 → 流式传输 → 完成。

接收：收到文件清单 → 岛自动展开接收卡片 → 展示对方名称、数量和大小 → 接受或拒绝 → 接收与校验 → 打开文件夹。确认期间优先显示接收任务，保留原有发送草稿。

托盘菜单“文件传输 · LocalSend”和内置工作台“文件传输”提供无需拖拽的入口。文件选择器提供键盘替代。面板收起不终止后台任务。

## 协议与网络

- 使用 UDP `224.0.0.167:53317` 发现设备，发送和响应 LocalSend v2 公告。
- 提供 `/api/localsend/v2/info`、`register`、`prepare-upload`、`upload`、`cancel`。
- 默认 HTTPS TCP 端口为 `53317`；被本机 LocalSend 占用时自动选择空闲端口，发现消息公告实际端口。
- 启动和网络变化后公告，定期刷新公告并过期设备记录；发送时以真实连接结果为准。
- 自动发现被禁用时，可以通过“连接地址”填写局域网 IPv4 地址和端口。
- Windows 防火墙应允许本应用在专用网络中的 TCP 入站与 UDP 发现。访客网络、AP 隔离或禁止多播的网络可能阻断自动发现或传输。
- 首版限 IPv4 局域网，不提供公网中继、账户体系或浏览器下载模式。

请求阶段仅传文件元数据。接收方明确接受后分配会话和逐文件随机令牌，文件以二进制流传输；不经通知 HTTP 入口、不进入渲染进程内存。

HTTPS 使用本机持久证书。发现的证书指纹用于后续连接校验；首次发现信息和显示名称不能作为经过配对验证的身份。首版每次接收均需要确认，不支持静默自动接收。兼容对方显式提供的未加密 HTTP 端点，设备卡片会显示“未加密”。

## 文件与生命周期

- 最多 200 个普通文件；文件夹、快捷方式和符号链接不在首版范围内。
- 同时允许一个发送会话和一个接收会话；接收忙时返回协议 `409`。
- 等待接收默认 90 秒；用户拒绝、发送方取消、等待超时有独立终态。
- 文件传输使用流、空闲超时及 SHA-256 校验；接收方接受协议允许的无哈希文件，但仍校验实际字节数。
- 接收文件先写入目标目录内独占创建的 `.part` 临时文件，校验成功后以不覆盖方式发布。同名文件自动加序号。
- 文件名拒绝目录穿越、Windows 保留名和替代数据流。接收前检查磁盘空间。
- 失败或取消清理活动临时文件；启动时清理超过一天的本功能临时文件。已完整收到的文件保留。
- 保存位置默认为 `Downloads/Activity Island`，支持更改；本机名称可设置。
- 设备名与目录配置、证书、最近 50 条已结束传输摘要保存在 `userData/transfers/`。历史版本为 1；摘要包含文件名与设备名，默认不写入日志。证书私钥与会话令牌不返回页面，源绝对路径不进入历史。当前无按天自动删除摘要的策略，由数量上限控制。
- LocalSend v2 基础协议未定义断点续传。本版中断后重新选择文件重试；不能把重试描述为断点续传。

## 代码边界

- 公共契约：`packages/platform-contracts/src/transfer.ts`，版本 1。
- Node 桌面传输服务：`apps/desktop/electron/transfers/service.ts`，不依赖 Electron UI。
- 桌面契约副本：`apps/desktop/electron/transfers/contracts.ts`，与公共契约同步；用于当前独立 CommonJS 构建。
- 拖放和窗口编排：桌面宿主及 preload。文件传输页面使用独立受限 IPC，其他插件页面不能调用传输管理接口。
- 内置界面：`apps/desktop/modules/file-transfer/`，无插件清单，复用宿主动画裁剪。

新增功能不需要改动通知接入、通知策略或通知历史。手机可先使用 LocalSend App；自己的手机端后续实现同一套协议，另行处理 Android/iOS 的文件授权与后台运行限制。

## 验证

```powershell
npm run test:transfer --workspace dynamic-island-host
npm run test:transfer-ui --workspace dynamic-island-host
npm run typecheck
npm test
```

服务测试使用真实 HTTPS、二进制流和独立协议请求，覆盖接收前无文件、中文名、多文件、零字节、同名避让、拒绝、超时、取消、错误令牌、校验失败与路径校验。

Electron 测试使用临时用户目录与临时接收目录，验证 Chromium 文件拖放、岛内设备选择、传输、接收自动展开、拒绝和错误提示。截图保存在系统临时目录。该测试不代替资源管理器原生拖放、两台电脑与 Android/iOS LocalSend 实机互传验收。

当前验证结果：6 项传输服务测试、Electron 双向收发流程、44 项原有平台测试、类型检查及 Windows 解包构建通过。已与本机运行中的 LocalSend 验证自动发现和设备信息接口，未向该实例发送真实用户文件。手机实机互传尚未验收。

已知基线问题：`test:contract` 中 18 项仲裁等单元检查通过，随后旧的 `phase-c-authoring.cjs` 因 `scripts/templates/plugin/dist/` 模板内容缺失而失败；该模板缺失不属于文件传输改动。
