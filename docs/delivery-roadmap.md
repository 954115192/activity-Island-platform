# 开发路线与交付计划

## 0.1：基础设施

目标：得到一个可运行的桌面壳层，并建立稳定的契约和清晰的功能边界。

- 定义领域事件公共结构与错误类型。
- 定义设备、权限、通知和传输接口。
- 建立桌面壳层生命周期与界面状态。
- 增加服务启动、关闭、健康状态和诊断接口。
- 增加契约测试和本地模拟服务环境。

验收标准：壳层可以通过正式服务将来使用的同一套接口，展示模拟通知和模拟传输状态。

## 0.2：Windows 通知流程

目标：形成第一个真实可用的完整功能流程。

- 接入 Windows 通知适配器。
- 增加内置本地触发接口，本机脚本可通过回环端口推送通知。
- 标准化来源、标题、正文摘要、时间和支持的操作。
- 增加去重与有保留上限的历史记录。
- 增加按应用过滤和暂停控制。
- 在灵动岛中提供通知模块（小岛预览、中岛详情）。
- 在托盘菜单提供统一的通知历史管理入口。

验收标准：真实 Windows 通知只展示一次，可以查看详情和打开来源，并且不会影响壳层稳定性。

## 0.3：设备身份与配对

目标：让电脑与手机建立可信关系。

LocalSend 文件互传先支持附近设备的临时会话，每次由接收方确认，无需先建立永久配对。持久配对与可信设备身份仍作为后续独立能力建设；发现时的名称不代表经过身份校验的用户。

- 实现一次性配对码或二维码流程。
- 保存可撤销的设备记录。
- 建立经过身份认证的局域网会话。
- 提供在线、离线、重连中和不可用状态。
- 在设置和工作台中增加设备管理。

验收标准：用户可以完成配对，在两端重启后重新连接，并撤销设备授权。

## 0.4：文件传输

目标：实现可靠的局域网双向传输。

首版实现见[内置 LocalSend 文件传输](localsend-file-transfer.md)：兼容 LocalSend v2、多文件拖放、发现设备、接收确认、进度、取消与校验。基础协议未提供断点续传，中断后重新选择文件重试；断点恢复保留为后续增强。

- 定义传输会话与分片协议。
- 增加接收确认、进度、取消、校验和重试。
- 增加受管理的临时存储与清理机制。
- 在灵动岛与工作台中提供传输模块。

验收标准：传输能从短暂断线中恢复，或显示可恢复的失败状态并提供重试入口。

## 0.5：手机通知同步

目标：将用户选定的手机通知展示到电脑。

- 增加手机端通知访问与本地过滤。
- 增加电脑端隐私过滤。
- 增加用于去重的稳定来源与事件标识。
- 增加静音、应用策略和正文可见性控制。
- 在手机系统允许的情况下接入来源操作。

验收标准：用户可以明确选择哪些手机通知类别能够到达电脑。

## 0.6：扩展平台

目标：让第三方开发使用安全、稳定的平台契约。

- 发布扩展清单与能力模型。
- 为通知、设备、传输和展示能力提供 SDK。
- 增加本地开发模拟器。
- 增加安装审核、权限提示、日志和兼容性检查。

验收标准：扩展可以通过授权接口创建传输或订阅通知，无需管理底层连接。

## 1.0：可长期日常使用的产品

- 完善升级与数据迁移。
- 增加服务隔离与崩溃恢复。
- 覆盖无障碍和减少动态效果设置。
- 增加隐私数据导出与删除控制。
- 增加运行诊断指标，默认排除私人内容。
- 明确支持策略与兼容性承诺。

## 暂缓范围

- 公共扩展市场。
- 公网中继或云存储替代方案。
- 完整手机投屏。
- 完整聊天客户端。
- 通用自动化语言。
